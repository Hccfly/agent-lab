# 安全与并发治理

## 1. 本次解决的风险

| 风险 | 原实现 | 当前控制 |
|---|---|---|
| 文件越权读取 | `Path(path).read_text()` 接受任意路径 | `resolve()` 后按根目录白名单判断父子关系 |
| session 路径穿越 | `sessions/{session_id}.json` 直接拼接 | 统一标识格式与长度校验，HTTP 层提前返回 422 |
| 写一半进程退出 | JSON 文件原地覆盖 | 同目录临时文件、`fsync`、`os.replace` 原子替换 |
| 同会话并发丢消息 | 两个请求同时读旧状态并各自覆盖 | 同一 session 的完整读—改—写事务串行化 |
| 向量并发写丢条目 | 每个实例覆盖自己的旧列表 | 锁内重读磁盘并合并本实例 pending items |
| 慢工具占满执行资源 | 工具直接同步执行且无上限 | 并发信号量、排队超时、执行超时 |
| 模型请求无限等待 | 未显式传请求 timeout | 所有聊天、流式、Planner、Summarizer、embedding 调用注入 timeout |

## 2. 路径白名单为什么不能用字符串前缀

以下判断是错误的：

```python
str(candidate).startswith(str(allowed_root))
```

如果白名单是 `D:/data/allowed`，攻击路径 `D:/data/allowed-evil/secret.txt` 也能命中前缀。
项目先将相对路径锚定到项目根目录，再对候选路径和所有白名单根目录执行 `resolve()`，最后判断：

```python
candidate == root or root in candidate.parents
```

这同时处理 `..`、同前缀目录和已有符号链接指向目录外部的情况。策略位于
`tools.read_file()` 内部，因此手写 Agent、ReAct、LangGraph 和 HITL 即使换入口，也必须经过它。

默认只允许读取 `agent-lab` 项目目录。需要增加目录时配置：

```dotenv
AGENT_ALLOWED_READ_ROOTS=D:/实习/agent-lab;D:/实习/共享资料
```

## 3. session_id 与 thread_id 校验

持久化标识必须满足：

```text
^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$
```

也就是以字母或数字开头，只包含字母、数字、点、下划线和短横线，最长 128。
`memory._path()`、CLI `/resume`、FastAPI `ChatBody` 和 checkpoint `thread_id` 复用同一规则。
HTTP 请求会在进入 Agent 前由 Pydantic 拒绝危险 ID，而不是运行到文件层才报 500。

## 4. 原子写与并发事务

`atomic_write_json()` 的写入顺序是：

```text
目标文件同目录创建临时文件
  -> 写入完整 JSON
  -> flush + fsync
  -> os.replace 原子替换目标
  -> 异常时清理临时文件
```

原子替换解决“半文件”，但不能单独解决“丢失更新”。因此 `run_agent()` 在有 session 时，
使用该 session 文件对应的 `RLock` 包住完整的加载、模型循环、摘要/RAG 和最终保存。
相同 session 串行，不同 session 使用不同锁，可以并发。

向量库采用 pending merge：每个实例只记录自己新增的条目，保存时在锁内重读最新磁盘状态，
按 UUID 去重合并，然后原子替换文件。这样多个并发 Agent 不会因为基于旧快照保存而互相覆盖。

## 5. 超时与限流

工具统一通过 `ExecutionGovernor`：

```text
获取并发槽位（等待超时 -> RateLimitExceeded）
  -> 在线程池执行
  -> 等待执行结果（执行超时 -> ExecutionTimeout）
  -> 工作真实结束后释放槽位
```

Python 无法安全杀死已经运行的线程，因此工具超时只让调用方及时返回错误，后台函数可能继续到自然结束。
关键设计是：超时后不能立刻释放槽位，否则慢任务还在运行，新请求又进入，会突破真实并发上限。
实现使用 Future 回调，在后台工作实际结束时才释放信号量。

配置项：

```dotenv
AGENT_MODEL_TIMEOUT_SECONDS=30
AGENT_TOOL_MAX_CONCURRENCY=4
AGENT_TOOL_TIMEOUT_SECONDS=10
AGENT_TOOL_QUEUE_TIMEOUT_SECONDS=0.25
```

模型 timeout 直接传给 OpenAI 兼容 SDK；工具超时异常在 Tool Calling 和 LangGraph 中会作为
Observation 回填模型，ReAct 也已增加同样的异常降级，不会直接炸掉循环。

## 6. 离线验收

```powershell
.venv\Scripts\python.exe -X utf8 tests\test_governance.py
.venv\Scripts\python.exe -X utf8 tests\test_server.py
```

`test_governance.py` 使用临时目录、并发线程和故障注入验证：

- 白名单内文件可读，`..` 和同前缀目录攻击被拒绝；
- 非法 session ID 被拒绝；
- `os.replace` 故障时旧 JSON 完整保留且临时文件被清理；
- 同一 session 两个并发对话最终保留两轮共四条消息；
- 8 个旧快照 VectorStore 并发保存后仍有 8 条；
- 超时任务真正结束前持续占用槽位，结束后恢复服务。

原有 memory/RAG 测试也补齐了 embedding stub，现在不会再误请求真实 embedding API。

## 7. 设计总结与边界

> 我把安全策略下沉到了共享基础层，而不是在某个 CLI 路由里做判断。路径授权在工具实现内部，
> 所有 Agent 范式不可绕过；会话 ID 在持久化层强校验，HTTP 层提前失败；文件写入采用同目录临时
> 文件加原子替换，同 session 再用事务锁防止丢失更新。执行层通过信号量和线程池统一限制工具，
> 特别处理了“调用方超时但后台线程仍在运行”的真实并发计数问题。

当前文件锁是进程内 `RLock`，适合本项目的单进程 CLI/Uvicorn 演示。多 worker 或多机器部署时，
应将 session/vector 状态迁到带事务或 CAS 的数据库，或使用跨进程文件锁。工具线程超时也不是强制
终止；对外部 HTTP 工具还应设置其自身连接/读取超时和可取消请求。
